# ADR-002: Use SQLite via Node's built-in `node:sqlite` for the Data tier

**Date:** 2026-10-07
**Status:** accepted

## Context

Holdings were stored in the browser's localStorage, which only lives in one
browser and can't be reached by a server. Connecting brokerage accounts
(SnapTrade) needs a backend to hold API secrets and to store connections,
accounts and synced positions alongside manual holdings. The store has to be
easy for my partner and instructor to run from a clean clone, with no extra
services.

## Decision

Store all data in a single SQLite file (`data/folio.db`) using Node's built-in
`node:sqlite` module. All database access lives in `src/data.js`; tests use an
in-memory database. CI moves from Node 20 (end of life) to Node 24, and the
project requires Node 22.13 or later.

Alternatives considered: a JSON file (no queries or transactions, awkward
once there are several related tables), PostgreSQL in Docker (a real
production database, but an extra service to install and run on conference
days), and the `better-sqlite3` package (mature, but a native npm dependency
that must compile or download binaries per platform).

## Consequences

There is nothing to install beyond Node, and the database is a real SQL store
with transactions that matches the "Portfolio Database" in the container
diagram. `node:sqlite` is still marked experimental, so Node prints a warning
(hidden by the npm scripts) and its API could change in a future Node release.
SQLite handles one server well but not many at once; if Folio ever needs
multiple servers or users at scale, only `src/data.js` would change to move to
PostgreSQL.
