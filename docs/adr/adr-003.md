# ADR-003: Use SnapTrade to connect brokerage accounts

**Date:** 2026-10-07
**Status:** accepted

## Context

Users should be able to import holdings from brokerages like Robinhood,
Charles Schwab, E*TRADE and Fidelity instead of typing them in. Integrating
each broker directly doesn't work: Robinhood has no official API for stock
holdings, and Schwab and E*TRADE each need their own developer approval,
login flow and data format. The project needs one integration that covers
many brokers, is free to develop against, and fits a one-semester scope.

## Decision

Use **SnapTrade**, a brokerage aggregator, with a Commercial API key and its
official Node SDK (`snaptrade-typescript-sdk`). Each Folio user is registered
as a SnapTrade user; until login exists there is one built-in user. Users
connect through SnapTrade's hosted Connection Portal with read-only access,
and Folio syncs their accounts and positions into SQLite. All SnapTrade code
lives in `src/snaptrade.js`; keys come from `.env`.

Alternatives considered: **Plaid Investments** (broad coverage and a free
sandbox, but real data requires a sales process and subscription) and
**direct broker APIs** (one integration per broker, and impossible for
Robinhood).

## Consequences

One integration covers 20+ brokers, and the free tier allows one connected
user, which is enough for development and demos. The app now depends on a
third-party service and an npm package; the SDK pinned a vulnerable `axios`
version, so `package.json` overrides it to a patched release. Synced data may
be up to a day old on the free tier. The SnapTrade user secret is stored in
plain text in the local database, which must change (encryption) before any
real deployment. Supporting more users later means real login, not a
different integration.
