# ADR-004: Keep user edits to synced holdings separate, and let the user decide on sync

**Date:** 2026-10-10
**Status:** accepted

## Context

Holdings imported from a brokerage are replaced with a fresh snapshot on every
sync. Users also need to edit or remove any holding, including synced ones
(a wrong average price, a position they don't want shown). If edits were
written straight into the synced data, the next sync would silently overwrite
them; if sync were blocked after an edit, the portfolio would drift away from
the brokerage.

## Decision

Store the user's edits and removals of synced holdings in their own table
(`brokerage_overrides`, keyed by account + ticker), separate from the
brokerage snapshot. The Domain tier applies them when building the portfolio
(`applyOverrides`) and compares them with each fresh sync (`findConflicts`).
Holdings the user never changed sync normally. When the user's changes
disagree with the brokerage, the UI lists them and asks "Keep my changes" or
"Use brokerage data". Changes that no longer matter (the holding was sold, or
an edit now matches the brokerage exactly) are dropped without asking.

Alternatives considered: let sync always overwrite user edits (simple, but
edits silently disappear), and only allow editing manual holdings (simple,
but users can't correct or hide brokerage data).

## Consequences

No sync ever loses a user's change without asking, and the brokerage data
underneath stays intact, so "Use brokerage data" can always restore it. The
cost is a fourth brokerage table and conflict logic, kept as pure functions in
the Domain tier so it is unit-tested without SnapTrade. A user who keeps their
changes is asked again on the next sync while the values still differ; if
that proves annoying, remembering the brokerage values at the time of the
edit and only asking when they change would remove the repeat prompt.
