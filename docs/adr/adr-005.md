# ADR-005: News from Finnhub with a Yahoo fallback; rule-based recommendations instead of an LLM

**Date:** 2026-11-07
**Status:** accepted, amended by [ADR-006](adr-006.md) (Claude now turns these rules' findings into the recommendations; the rules still compute every number)

## Context

UC4 needs two things: news about what the user owns, and recommendations a
beginner can act on. The app must still run from a fresh clone with no keys
(for peer review and grading), stay within free API tiers, and be testable
without the network. News sources tag stories loosely: on real data, Finnhub
tagged "Booking vs. DoorDash: which is the better buy?" as Apple news, so
"what the source tagged" is not the same as "about this holding".

## Decision

**News source.** `src/news.js` fetches news per ticker from a provider list,
like `src/prices.js` (Open/Closed): Finnhub company news (last 7 days) when
`FINNHUB_API_KEY` is set, otherwise Yahoo Finance search, which needs no key. If
Finnhub has nothing for a ticker (most funds), Yahoo is tried. Results are
cached for 15 minutes, only the 10 largest holdings are looked up, and a failing
ticker keeps its last cached news. Finnhub was chosen because the project
already uses its free key for backup prices (60 calls/minute), so there's no
new signup. Alternatives considered: NewsAPI (free tier is for development only,
and its articles aren't tied to tickers), and Alpha Vantage's news sentiment (25
calls/day on the free tier, too few for a portfolio that refreshes).

**Matching and recommendations are Domain rules** in `src/insights.js`, pure
functions with no I/O:
- An article counts for a holding when its headline or summary names the
  ticker or the company (company names come free with Yahoo's price data).
  Articles that are only tagged are dropped for stocks and kept, ranked low,
  for funds, whose names rarely appear in headlines. Stories are deduplicated
  and ranked by where the holding is named, its share of the portfolio, and how
  recent the story is.
- Sentiment is a small positive/negative word list applied to the **headline
  only**. Summaries made it worse on real data ("one of the ugliest stretches
  on record" counted as positive).
- The diversification score is based on the Herfindahl index of value weights
  (as "effective holdings"), with a fund counting as 10 holdings' worth of
  spread. Recommendations are a list of rules (`RULES`): low diversification,
  any stock over 25%, large losses, large gains worth rebalancing, a week of
  mostly negative or positive news, and unpriced holdings.

Alternative considered: have an LLM read the news and write recommendations.
It would read better, but it needs a paid key, the output changes from run to
run (it can't be unit-tested or explained to a user the same way twice), and
it can state financial advice with more confidence than the data supports.

## Consequences

UC4 works with no key, and better with the existing Finnhub key. Every rule
and threshold is in one file, unit-tested, and explainable ("NVDA is 27% of
your portfolio, over the 25% limit"). Adding a recommendation means adding a
rule to `RULES`. The costs: word-list sentiment misreads sarcasm, negation and
mixed headlines, so it only drives a recommendation when several headlines in
a week lean the same way; Folio can't see inside funds, so overlapping funds
look more diversified than they are; and Yahoo's search endpoint is unofficial
and may change. An LLM summary could later be added as an optional layer on
top of these rules without replacing them.
