# ADR-006: Claude writes the recommendations from Folio's numbers, and Folio checks every number

**Date:** 2026-11-07
**Status:** accepted (amends [ADR-005](adr-005.md))

## Context

ADR-005 made recommendations rule-based. The rules were then made specific
(share counts and dollar amounts to reach a target, the gain or loss a sale
would realize, the tax treatment from purchase dates, the headlines behind a
news warning), but they still read as separate findings: TSLA's concentration,
NVDA's concentration and NVDA's gain are three cards, when the useful advice is
one move ("this one NVDA sale does both"). Combining findings into a few
prioritized moves, with concrete steps and a plain summary on top, is what a
language model is good at. ADR-005's objections still apply: an LLM costs
money, its output varies, and it can invent facts, including numbers.

A first version had Claude add notes next to each rule finding; it was
replaced because the findings stayed fragmented.

## Decision

Claude writes the summary and 3-6 recommendations from Folio's findings; the
rules still compute every number, and the Domain tier verifies the answer.

- **Model: Claude Haiku 5.5 (`claude-haiku-5-5`), the cheapest current Claude
  model** ($0.10 / $0.50 per million input / output tokens). One answer is
  about 4K tokens in and 1-2K out, roughly $0.001. The cheapest OpenAI models
  were priced the same per token at the time (Oct 2026), so cost didn't decide
  between providers; Claude was kept because the integration (SDK, structured
  outputs, error handling, tests) already existed. `ANTHROPIC_MODEL` can pick a
  stronger model; server-side refusal fallbacks are sent only to models that
  support them (Haiku 5.5 doesn't).
- **Facts in.** `src/advice.js` (`buildAdvisorBrief`) gives Claude each
  holding's shares, value, average cost, price, gain/loss and holding start,
  the risk score, Folio's findings with their exact amounts and ids, and
  matched headlines. Never account details or brokerage data.
- **Structured out.** `src/claude.js` (Data tier, the only file that calls the
  Claude API) asks for JSON: `summary` and `recommendations[{title, why, steps,
  ticker, priority, basedOn}]`, where `basedOn` lists the finding ids used. The
  prompt tells Claude to use only numbers from the brief and not to calculate.
- **Every number checked.** `validateAdvice` extracts every number from each
  recommendation and drops the recommendation if any number isn't in the brief
  (amounts of 100 or more within 1%, smaller ones within rounding; dates only
  vouch for their year; 0-3 are allowed as wording). A summary that fails is
  replaced by the rules' summary. Tickers the user doesn't hold and unknown
  finding ids are removed. The page says how many suggestions were removed.
- **The working stays visible.** The findings remain on the page, collapsed
  under "How Folio worked these out", and each recommendation names the
  findings it's based on.
- **Always works without it.** With no `ANTHROPIC_API_KEY`, or when Claude
  fails (bad key, rate limit, offline, refusal, unusable answer),
  `fallbackAdvice` writes the summary from a template and the findings are
  shown as the recommendations, with the reason on the page.
- **Cost control.** Answers are cached for 6 hours per brief, concurrent
  requests share one call, and the page only asks while the Recommendations tab
  is open and the holdings have changed, or on Regenerate.

Alternatives considered: letting the LLM calculate amounts (it gets arithmetic
wrong, and there'd be nothing to check it against), and no LLM at all
(specific, but fragmented, which is ADR-005 as it was).

## Consequences

Users get a short list of specific, prioritized moves that combine related
findings, with the exact numbers and how they were worked out one click away.
A wrong number can't reach the page unless it happens to match an amount in
the brief: the check compares values, not what they measure, so "1,000 shares"
would pass if $1,000 is in the brief. Wording can still be wrong, which is why
the page says the text is AI-written. Tests use a fake client, so they check
the request and Folio's handling of answers, not the quality of Claude's
writing. The cost is one dependency (`@anthropic-ai/sdk`) and about a tenth of
a cent per answer.
