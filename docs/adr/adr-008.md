# ADR-008: Draw charts in plain SVG, rebuild value history from daily closes, and compare with "the same money in an index fund"

**Date:** 2026-11-20
**Status:** accepted

## Context

UC3 needs a chart of the portfolio's value over time, gain/loss by holding,
and allocation, and the final version adds a comparison with major indexes.
Folio never stored past prices or daily portfolio values, users add holdings
with purchase dates years in the past, and synced brokerage positions have no
purchase date at all. The app must still run from a fresh clone with no keys or
background jobs, and the charts must be readable without a mouse and by
colorblind users.

## Decision

- **Plain SVG, no chart library.** `public/charts.js` draws the three charts
  as SVG and HTML. It only draws data it's given: no `fetch`, no business
  rules. Every chart has a hover/keyboard layer (arrow keys move day by day),
  a "Show as table" view, and colors checked with a colorblind palette
  validator. The comparison line is also dashed, so color is never the only
  way to tell the lines apart.
- **Value history is rebuilt on request, not stored.** `prices.getHistory`
  fetches Yahoo Finance daily closes (weekly for 5Y, cached for an hour), and
  the Domain (`buildValueHistory`) values each purchase from its date on. The
  last point uses the live price, so the chart ends on the summary total.
  Synced shares are dated from the stored brokerage buy history, newest buys
  first (shares sold are taken to be the oldest), at the position's average
  cost so the invested line still ends on the cost basis. Shares the history
  doesn't cover count from the chart's start, and the page says so.
- **The comparison is the same money in an index fund.** A purchase also
  "buys" the fund (SPY, QQQ, DIA or VTI, listed in `domain.BENCHMARKS`) for
  the same amount on the day the chart starts counting it: its purchase date,
  or the chart's first day for older purchases. Both lines therefore start
  together, money added later goes into both on the same day, and the gap is
  only the difference in performance.

Alternatives considered: a chart library (Chart.js, Recharts), which adds a
dependency and, for Chart.js, draws on a canvas, so the keyboard reading and
table view would still have to be built by hand; storing a daily snapshot of
each portfolio, which needs a scheduled job and leaves new users with an empty
chart until days pass; and plotting the index's own return rebased to 100,
which ignores when the user put money in and can show "you beat the market"
when the timing of deposits did the work.

## Consequences

The charts need no new dependency and work for holdings added a minute ago.
The cost is that history depends on Yahoo's unofficial chart endpoint: a
ticker without history is left out with a note, and a comparison fund that
fails to load leaves the portfolio chart in place with a message. Neither line
counts dividends, sold positions don't appear (the history is built from what
the user holds today), the first-in-first-out dating of synced shares is an
assumption, and index funds stand in for the indexes themselves (they trail
them by their small fees).
